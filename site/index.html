MCP server · runs on your machine

Give Claude a video studio
and a rendering desk.

remotion-viz is a local MCP server for Claude Desktop: programmatic video with Remotion, plus SVG and HTML rasterization — using your own Chrome, fonts and files. Nothing leaves your machine; there is no server to sign into, because there is no server anywhere but yours.

Download the .mcpb Source on GitHub

What Claude can do with it

Thirteen tools. Ask in plain language — “turn this data into an animated chart video”, “rasterize this SVG”, “screenshot this HTML dashboard” — and Claude drives these on your machine.

Programmatic video (Remotion)

remotion_init_project

Scaffold a minimal, working Remotion 4 project.

remotion_list_compositions

List compositions in a project; doubles as a compile check.

remotion_render_still

Render one frame to PNG and attach it to the response.

remotion_render_video

Render a composition to video or audio.

remotion_start_studio

Start the Remotion Studio dev server — a full visual editor on localhost.

remotion_stop_studio

Stop a Studio this extension started — after asking the OS the PID is really ours.

Static visuals

viz_render_svg

Rasterize SVG to PNG with resvg — native, no browser needed.

viz_render_html

Screenshot HTML to PNG with your local Chrome, under a deny-all network policy.

viz_validate_svg

Lint SVG against the rules renderers actually enforce, with a fix per finding.

viz_compare

Pixel-diff two PNGs — verify a fix instead of assuming it.

Diagnostics

remotion_check_environment

Diagnose why Remotion commands fail, with a specific fix per problem.

remotion_ensure_browser

Pre-download the Chrome Headless Shell Remotion renders with.

remotion_get_workspace_info

Report the workspace root that file paths resolve against.

The security envelope

A server that spawns processes and writes files should be hard to reach and easy to audit. That is most of the engineering here.

  • stdio only. The HTTP transport was removed by decision, not omission — the only thing that can reach this server is the client that launched it.
  • Deny-all network for rendered HTML. Every request a page makes is aborted before egress and recorded as a network_block audit event.
  • A pixel budget before allocation. A 120-byte SVG declaring an absurd viewBox once meant a 288 GB allocation; now oversized renders are refused up front, with the math shown.
  • Filesystem discipline. Paths resolve inside a workspace you choose; traversal attempts are refused and audited. SVG file references — a quiet read primitive in most rasterizers — are rejected.
  • Honest process control. Stopping a Studio verifies with the OS that the PID still belongs to the Studio we started before any signal is sent.
  • An audit log you can read. Every call, refusal and network block lands in a rotated JSONL log; a bundled dashboard renders it as one self-contained HTML file.

Provenance you can check

Every release is built by CI from a locked dependency tree and signed keylessly with Sigstore cosign. The bundle’s contents are host-independent and gated: six platform binaries (win32, macOS and glibc Linux, x64 and arm64 each), fetched against the committed lockfile’s hashes, executed on all six platforms in CI before anything ships.

cosign verify-blob \
  --certificate remotion-viz-<version>.mcpb.pem \
  --signature   remotion-viz-<version>.mcpb.sig \
  ...           # full recipe, including the exact identity to require,
                # lives in the README: “Verifying a release”

The recipe’s canonical copy — with the certificate identity the workflow actually signs under — is in the README, kept in lockstep with the release workflow on purpose.

Why it is shaped this way

Three architecture decision records carry the reasoning; the short version:

ADR-1 — stdio only, no HTTP. For a server that runs code, the transport question is whether the attack surface stays behind one trusted client. It does.
ADR-2 — no gateway. With no network boundary there is nothing for a gateway to guard; rate limiting and audit live in-process, where the context is.
ADR-3 — validate first, isolate what’s left. The only native code in-process is the rasterizer; its one known crash path was closed by input validation, and the residual risk is stated, not hidden.

Install

Requires Node 22+ on the host. Download the latest .mcpb and open it with Claude Desktop — the manifest declares the tools and the permission surface, and Claude Desktop does the rest. Running from source (Claude Code, or any MCP stdio client) is covered in the README.
