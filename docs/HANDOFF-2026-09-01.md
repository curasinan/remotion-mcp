## 0. Start here: the bundle will fail its own gate on the next release

`v1.2.1` passed the size gate by **32 KB**.

```
baseline  20,463,297
ceiling   22,509,627   (+10% tolerance)
actual    22,477,304   ← 99.86% of ceiling, 9.84% growth
```

**Where the growth is, traced:**

```
puppeteer-core@24.43.1
  └─ @puppeteer/browsers@2.13.2
       └─ tar-fs@3.1.3
            optionalDependencies: { bare-fs ^4.0.1, bare-path ^3.0.0 }
                 bare-fs@4.8.0   engines: { bare: ">=1.28.0" }
                 bare-url@2.5.1
```

`bare-fs` describes itself as *"Native file system operations for Bare"* and
declares `engines: { bare: … }`. It is a filesystem library for the **Bare
runtime**, which this server never runs on. Measured in the extracted `v1.2.1`
bundle: `bare-url` 4 MB, `bare-fs` 2 MB, out of 66 MB unpacked / 21.4 MB zipped.

**The obvious fix is a trap.** `npm ci --omit=dev --omit=optional` in
`scripts/build-bundle.mjs` would drop them — and would also break the bundle,
because `@resvg/resvg-js` resolves its platform `.node` addon *through*
optionalDependencies. That is the entire reason `NATIVE_TARGETS` exists in
`build-bundle.mjs` and why the six binaries are fetched explicitly.

So this needs a surgical answer: prune `bare-*` specifically after install, or
establish that they are genuinely required and raise the baseline deliberately.
**Do not raise the baseline just to make the gate pass** — that converts a working
gate into a rubber stamp.

*and* the README recipe together.

## 5. Two bugs worth understanding before touching this code

### The macOS hang was never a timeout

`waitUntil: "networkidle0"` does not mean puppeteer counts requests. It waits for
Blink to emit `Page.lifecycleEvent{networkIdle}`, and on the macOS runner Blink
sometimes never emits it.

```
run 33322657864  macos 20/22    9,809ms /  11,470ms   PASS / PASS
run 33323021866  macos 20/22   38,742ms /  44,770ms   FAIL / FAIL
run 33425660434  macos 20/22  101,077ms /   8,517ms   FAIL / PASS
run 33431085855  macos 20/22   98,329ms /  95,131ms   FAIL / FAIL
```

`git diff --stat 73b4e73 e6c685f` is **empty** — the first two runs are
byte-identical trees on the same runner image eight minutes apart, one green one
red. Timing was bimodal (8.5–11.5 s or past the deadline, never between), and
failure time tracked whatever the deadline was (30 s → 38.7 s, 90 s → 98.3 s),
which rules out **any** timeout value as a fix. The number was raised twice before
anyone measured.

Dropping the wait is correct on the merits: `viz_render_html` renders
caller-supplied markup under a deny-all network policy, so every request is
aborted before egress. Waiting for the network to go quiet waits for a condition
the policy already guarantees.

**If a future page needs post-load settling** — most plausibly a `data:`-URI
`@font-face`, since `load` does not guarantee `document.fonts.ready` — add an
explicit wait for *that specific thing* inside the same `withDeadline` closure.
Do not reach back for `networkidle0`.

### Fixed wall-clock guesses failed three times

| Where | The guess | Fix |
| --- | --- | --- |
| `TIMEOUT_PAGE_LOAD_MS` doubling as `protocolTimeout` | 30 s | split the constants; own deadline |
| `process-leak.test.mjs` SIGKILL grace | 4 s | poll to condition, 15 s cap |
| `studio.test.mjs` process-table wait | 700 ms | poll to condition + warm PowerShell |

The third is the instructive one. The first poll fix **still went red** — its own
failure message showed `readCommandLine` never succeeded once in 15 s, because it
spawns PowerShell under a 5 s `spawnSync` cap and cold start on a contended runner
exceeds it. Every call was killed before the file cache warmed, so every call was
the first call. No polling deadline escapes that; the fix pays the cold start once,
outside the cap.

A failure message that named *what was missing* is what produced the correct
diagnosis.

## 6. The working method

Every gate on this branch was proven against a known-bad input before being
trusted. That caught four defects that would otherwise have shipped green:

- ESLint's `languageOptions` silently clobbered by object-spread ordering
- a bundle verifier whose negative test picked the one case already covered
- an extract-directory guard that deleted files it did not own — including a
  signature matching this repo's own `build/` staging tree
- two version-sync tests that asserted *something* threw, not *what*

One refinement the work produced: **a guard's proof must include the input that
makes it permit, not only the input that makes it refuse.** Both of Task 6's
findings lived in that half.
